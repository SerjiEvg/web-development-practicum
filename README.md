# Практикум по технологиям создания web-приложений

Репозиторий содержит материалы первой части практикума по веб-разработке: методический PDF, материалы индивидуальных вариантов, графические ресурсы.

Практикум включает **7 практических работ** и выстроен от сетевой диагностики и HTTP к рабочему окружению, HTML, CSS и адаптивной компоновке. В исходном практикуме первая часть рассчитана на 68 учебных часов.

## 3. Что делать по каждой работе

### Практическая работа 1 — TCP/IP

Освоить базовые команды диагностики сети: `ipconfig`, `hostname`, `ping`, `tracert`, `netstat` и связанные средства. Получить параметры TCP/IP рабочего места, проверить доступность выбранного ресурса и исследовать маршрут до него. Все результаты сопровождаются скриншотами и объяснениями.

**Основной артефакт:** отчёт.

Подробнее: [`works/01-tcp-ip/README.md`](works/01-tcp-ip/README.md)

### Практическая работа 2 — HTTP

Работать с предоставленной трассировкой в Wireshark. Найти HTTP Request/Response, определить количество и объём пакетов, применять фильтры `http` и `tcp`, разобрать GET-запрос, заголовки и ответ сервера.

**Основной артефакт:** отчёт с анализом трассировки.

Подробнее: [`works/02-http/README.md`](works/02-http/README.md)

### Практическая работа 3 — среда разработки

Установить VS Code, Live Server, Git; создать `index.html`, запустить локальный сервер, разместить страницу через GitHub Pages. Дополнительно изучаются ngrok, Postman и Chrome DevTools.

**Основной артефакт:** рабочий GitHub-репозиторий и опубликованная страница.

Подробнее: [`works/03-dev-environment/README.md`](works/03-dev-environment/README.md)

### Практическая работа 4 — базовый HTML

Создать HTML-документ и отработать базовые теги, структуру документа, заголовки, абзацы, ссылки, изображения, списки, таблицы, формы и метаданные. В материалах репозитория находятся графические ресурсы `signs/`.

**Основной артефакт:** HTML-страница с корректными путями к ресурсам.

Подробнее: [`works/04-html-basics/README.md`](works/04-html-basics/README.md)

### Практическая работа 5 — HTML5

Перейти от просто работающей разметки к семантической структуре: `header`, `nav`, `main`, `section`, `article`, `aside`, `footer`. Использовать варианты макетов и подготовить публикацию через GitHub Pages.

**Основной артефакт:** семантически организованная HTML5-страница.

Подробнее: [`works/05-html5-structure/README.md`](works/05-html5-structure/README.md)

### Практическая работа 6 — CSS3

Изучить модель коробки, селекторы, каскад и наследование. В расширенном варианте отработать псевдоклассы, псевдоэлементы, `transition`, `transform`, `box-shadow`, `border-radius`, прозрачность и анимации. Проверять результат в DevTools и публиковать страницу через GitHub Pages.

**Основной артефакт:** HTML/CSS-проект.

Подробнее: [`works/06-css3/README.md`](works/06-css3/README.md)

### Практическая работа 7 — компоновка

Реализовать выбранный визуальный вариант как адаптивную страницу. Использовать Flexbox и CSS Grid, настроить Desktop/Mobile, медиазапросы и перестройку блоков на контрольной границе 768 px. Макет нельзя реализовывать единым фоновым изображением: элементы должны быть собраны средствами HTML/CSS.

**Основной артефакт:** адаптивный HTML/CSS-проект.

Подробнее: [`works/07-layout/README.md`](works/07-layout/README.md)

## 5. Как работать студенту

Рекомендуемый порядок:

```text
1. Изучить соответствующий раздел PDF
        ↓
2. Открыть README конкретной практической работы
        ↓
3. Выбрать свой вариант, если работа предполагает варианты
        ↓
4. Создать/изменить файлы проекта
        ↓
5. Проверить результат в браузере и DevTools
        ↓
6. Оформить отчёт и скриншоты
        ↓
7. Сделать commit и push в GitHub
        ↓
8. Для HTML/CSS работ — опубликовать результат через GitHub Pages
        ↓
9. Передать преподавателю ссылку на репозиторий/страницу
```

## 6. Как преподавателю использовать репозиторий

1. Дать студентам ссылку на публичную часть репозитория.
2. Назначить индивидуальный вариант из соответствующего каталога `variants/`.
3. Для работ 1–3 использовать задания из PDF и локальные README.
4. Для работ 4–7 использовать графические материалы из `works/`.

## 7. Требования к студенческому проекту

Для работ, связанных с HTML/CSS, рекомендуется придерживаться структуры:

```text
student-project/
├── index.html
├── css/
│   └── style.css
├── js/
│   └── script.js              # если используется
├── images/
│   └── ...
└── README.md
```

`README.md` студенческого проекта желательно содержит:

- название работы;
- номер варианта;
- краткое описание реализации;
- использованные технологии;
- ссылку на GitHub Pages;
- сведения о проверке адаптивности;
- известные ограничения, если они есть.

## 8. Git: рекомендуемый рабочий процесс

```bash
git clone <URL-репозитория>
cd <репозиторий>

git status
git add .
git commit -m "Практическая работа N: готово"
git push
```

Для каждого задания желательно делать отдельный понятный commit. Не добавляйте в репозиторий токены ngrok, пароли, ключи API и другие секреты.

---

## 9. GitHub Pages

Для работ с публикацией:

1. Убедитесь, что в публикуемой директории есть `index.html`.
2. Загрузите исходный код в GitHub.
3. В настройках репозитория включите GitHub Pages.
4. Выберите источник публикации согласно настройкам репозитория.
5. Проверьте страницу на Desktop и Mobile.
6. Передайте преподавателю URL опубликованной страницы.

- [ ] Код находится в GitHub.
- [ ] Нет секретов и токенов в коммитах.
- [ ] Все пути к изображениям и CSS корректны.
- [ ] `index.html` открывается без критических ошибок.
- [ ] DevTools Console не содержит необъяснимых ошибок.
- [ ] Network не показывает отсутствующие обязательные ресурсы.
- [ ] Для CSS-работ проверен Box Model и каскад.
- [ ] Для работы 7 проверены Desktop и Mobile.
- [ ] Отчёт и необходимые скриншоты подготовлены.
- [ ] Ссылка на репозиторий/страницу передана преподавателю.
